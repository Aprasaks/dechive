# 콘텐츠와 페이지 기준

## 공통 규칙

- 모든 콘텐츠는 고유 UUID를 가진다.
- slug는 주소 표현이며 정체성이 아니다.
- `status(draft/published/archived)`와 `visibility(public/private/unlisted)`를 분리한다.
- 초안은 자동 저장으로 갱신하고, 발행 시 immutable revision을 만든다.
- 대표 이미지, 작성일, 마지막 검증일, 출처, 태그, 명시적 관계를 콘텐츠로 관리한다.
- 태그는 3~5개의 정규화된 색인이다. 계층과 학습 순서를 대신하지 않는다.

## Knowledge

하나의 독립된 개념이나 질문을 설명한다. 강제 읽기 순서는 두지 않는다.

상세 페이지 순서:

1. 제목
2. 작성일과 마지막 검증일
3. 대표 이미지
4. `이 글에서 알아야 할 것`
5. 본문과 목차
6. 주장 단위 각주와 출처 목록
7. 먼저 알아야 할 지식(필요할 때 최대 3개)
8. 다음으로 읽을 지식(직접 이어질 때 1~3개)
9. 직접 연결되는 Lecture와 Practice
10. 태그
11. 댓글(후속 단계)

목차는 H2가 3개 이상일 때 자동 표시한다. 데스크톱에서는 오른쪽 고정 목차, 모바일에서는 접을 수 있는 목차로 제공한다.

## Lecture

여러 Knowledge를 의미 있는 학습 순서로 묶고 하나의 YouTube 영상과 자료로 설명한다. LMS가 아니다.

상세 페이지 순서:

1. 제목과 날짜
2. 강의의 전반적인 설명
3. `이 강의에서 알아야 할 것`
4. 필수 Knowledge
5. YouTube 영상
6. 주요 주제와 타임스탬프
7. 강의자료 미리보기와 다운로드
8. 연결된 Practice
9. 태그와 댓글(후속 단계)

## Practice

하나의 완성된 결과물을 먼저 보여주고 제작 과정을 세로로 설명한다.

상세 페이지 순서:

1. 제목과 날짜
2. 완성 결과 화면·이미지·영상·데모
3. 무엇을 만드는가
4. 필요한 Knowledge와 Lecture
5. 도구·재료·비용
6. 실습 자료
7. 단계별 제작 과정
8. 자주 생기는 실패와 해결
9. 최종 검증 체크리스트
10. 완성 파일과 관련 Practice
11. 태그와 댓글(후속 단계)

목록은 작은 카드 격자가 아니라 큰 완성 화면과 설명을 한 항목씩 세로로 배치한다.

## AI Update

자동 뉴스 피드가 아니다. 날짜별로 반드시 알아야 할 변화만 기록한다. 의미 있는 변화가 없는 날짜는 만들지 않는다.

상세 페이지 순서:

1. 날짜와 제목
2. 확인할 변화 요약
3. 카드뉴스 이미지
4. 무엇이 바뀌었는가
5. 이전과 무엇이 다른가
6. 사용자에게 미치는 영향
7. 지금 확인하거나 바꿀 것
8. 공식 출처
9. 영향을 받는 Knowledge·Lecture·Practice
10. 태그와 댓글(후속 단계)

목록은 달력이 아닌 세로형 날짜 아카이브로 제공한다.

## Books

사이트 안에서 결제하지 않는다. 책을 왜 읽어야 하는지 충분히 설명한 뒤 알라딘·교보문고·예스24 등의 외부 판매처로 연결한다.

상세 페이지 순서:

1. 표지와 서지 정보
2. 왜 읽어야 하는가
3. 다루는 문제와 질문
4. 대상 독자
5. 읽고 얻는 것
6. 목차
7. 미리보기
8. 페이지·형식·ISBN
9. 외부 판매처 링크
10. 연결된 콘텐츠
11. 태그와 댓글(후속 단계)

## 연결 규칙

- 본문에서 이해에 필수적인 첫 등장에만 링크한다.
- 같은 태그라는 이유만으로 관련 글을 자동 노출하지 않는다.
- 링크를 없애도 이해와 다음 행동에 문제가 없다면 넣지 않는다.
- 관계는 `prerequisite`, `next`, `uses`, `explains`, `practice_for`, `affected_by`처럼 의미를 명시한다.
